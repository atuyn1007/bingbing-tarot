# 万象归一阵第三阶段设计规格

## 目标与边界

第三阶段把第二阶段已经冻结的六轮起卦结果接入正式易经知识层，并完成“见象 × 观势”结果页。现有 `unityAlgorithm.js`、六轮顺序、正位等于 2、逆位等于 3、动爻规则和文王卦序均不修改。

本阶段只展示 18 张塔罗图像和本卦、动爻、变卦的基础易经资料。不生成塔罗牌义、逐爻融合解释、综合结论、行动建议、吉凶判断或 AI 内容。

## 已确认方案

采用“结构事实、可编辑知识、结果快照”三层分离方案：

1. 结构事实层完整保存八卦和六十四卦的稳定身份、卦序、上下卦、六爻线型、Unicode 与名称键。
2. 可编辑知识层按卦和爻分别保存经典原文、现代简释、关键词、语言、内容版本、状态与来源。经典原文和现代内容不得共用字段。
3. 结果适配器把第二阶段计算结果与指定知识版本结合，形成只供展示和历史回放使用的知识快照。适配器不得重新抽牌或重新计算卦象。

不采用以下方案：

- 在 `UnityResultPage.jsx` 内硬编码卦辞或爻辞：违反知识层边界，无法版本化和测试。
- 结果页每次直接读取“当前最新”知识：知识更新会改变旧结果，不符合历史回放要求。
- 一次性生成全部 64 卦与 384 爻现代文案：内容未经审校，违反本阶段真实性要求。

## 知识数据结构

新增独立目录 `src/data/unity/`：

- `trigrams.js`：8 个八卦的稳定结构记录。
- `hexagrams.js`：64 卦完整结构索引，包括稳定 ID、文王卦序、名称键、上下卦、六爻线型和 Unicode。
- `hexagramContent.js`：已录入卦级内容，按 `hexagramId + locale + contentVersion` 定位。
- `lineTexts.js`：已录入爻级内容，按 `hexagramId + linePosition + locale + contentVersion` 定位。
- `keywords.js`：受控关键词 ID 与本项目现有语言标签。
- `sources.js`：经典原文和现代编辑内容的来源及版本元数据。

卦级内容至少分开保存：

```js
{
  hexagramId,
  locale,
  contentVersion,
  contentStatus,
  canonical: { originalText, sourceId },
  modern: { summary, editorSourceId },
  keywordIds: []
}
```

爻级内容至少分开保存：

```js
{
  lineId,
  hexagramId,
  linePosition,
  polarity,
  locale,
  contentVersion,
  contentStatus,
  canonical: { originalText, sourceId },
  modern: { summary, editorSourceId }
}
```

64 卦结构索引必须完整。传统正文只录入经过核对、足以覆盖自动测试和界面开发的少量真实卦例；未录入的卦或爻返回明确的 `unavailable` 状态，不使用其他卦内容代替，不临时生成文本。

首批测试内容以乾、坤、泰、否及测试变化路径实际需要的少量卦例为主。提交时必须在交付说明中准确列出实际录入范围和仍缺失的范围。

## 知识查询适配器

新增 `src/unityKnowledge.js`，职责限定为：

- 通过文王卦序或稳定 ID 定位结构事实。
- 按语言和内容版本读取卦级资料。
- 按卦与 1–6 爻位读取动爻资料。
- 将受控关键词 ID 映射为本地化标签。
- 对缺失内容返回结构化的不可用状态。
- 校验算法给出的上下卦和六爻线型与知识结构一致；不一致时拒绝生成展示快照。

适配器输出：

```js
{
  schemaVersion: '1.0',
  knowledgeVersion,
  locale,
  primary: {
    structure,
    canonical,
    modern,
    keywords,
    contentStatus
  },
  movingLines: [
    {
      lineIndex,
      lineValue,
      polarity,
      age,
      canonical,
      modern,
      contentStatus
    }
  ],
  changed: null | {
    structure,
    canonical,
    modern,
    keywords,
    contentStatus
  }
}
```

第二阶段的 `result.primaryHexagram`、`result.changedHexagram` 和 `result.rounds` 仍是计算事实来源。展示快照是新增的派生数据，不改变冻结字段。

## 无动爻语义

算法规范保持不变：无动爻时，计算得到的变卦线型与本卦相同。

展示语义必须单独处理：当 `movingLineIndexes` 为空时，知识适配器令 `changed` 为 `null`。结果页显示“本次无动爻”及稳定说明，不渲染变卦模块，也不显示“本卦即变卦”。这不会改变原始 `changedHexagram` 计算事实。

## 结果快照与回放

新增用户作用域的 Unity 结果持久化模块。起卦完成后保存：

- 原始问题；
- 18 张牌及固定正逆位；
- 六轮、六爻、本卦、动爻和算法变卦；
- 当前知识版本的中、英、意展示快照；
- 完成时间和 schema 版本。

重新打开结果时只校验并读取该快照，不调用随机函数，不创建新 casting session，不重新计算牌序。语言切换只选择同一结果中对应语言的知识快照，不改变牌、爻或卦。

本阶段不修改 Supabase 表，也不把完整 Unity 数据压入现有 `tarot_history.card_name`。只保留最近一次完整 Unity 结果的本地用户作用域快照，并在 Unity 介绍页提供重新打开入口。

## 页面组件

`UnityResultPage.jsx` 只负责页面组合。新增或拆分以下组件：

- `UnityTarotArchive`：左侧“见象”，显示六行、每行三张牌。
- `UnityTarotPopover`：桌面悬停／焦点和移动端点击时显示爻位、牌序、牌名、正逆位。
- `UnityHexagramSection`：本卦或变卦的古籍阅读段落。
- `UnityMovingLinesSection`：动爻及对应爻辞段落。

左侧视觉顺序为上爻、五爻、四爻、三爻、二爻、初爻，通过反转展示数组实现；`result.rounds` 始终保持初爻到上爻。默认不显示牌名、关键词或牌义。

右侧按以下顺序展示：

1. 本卦：卦象、卦名、卦序、上卦、下卦、卦辞原文、现代简释、关键词。
2. 动爻：爻位、阴阳、老阴／老阳、爻辞原文和现代简释。
3. 有动爻时显示变卦及固定帮助说明；无动爻时显示稳定说明。

原文和现代解释使用独立标题、独立 DOM 区块及不同排版，不通过字符串换行判断内容类型。资料缺失时显示本地化的“知识档案待录入”，不得显示空白容器。

## 交互与无障碍

塔罗缩略图使用按钮语义，点击区域不小于 44px。桌面端悬停和键盘聚焦显示轻量浮层；移动端点击切换浮层，重复点击或点击外部关闭。浮层只包含爻位、牌序、牌名和正逆位。

所有装饰性星轨和天文符号设置 `aria-hidden="true"`。卦象自绘六爻提供完整 `aria-label`。动爻高亮使用太阳金，不使用红色。支持 `prefers-reduced-motion`，不添加持续动画。

## 响应式布局

桌面端使用左宽右窄双栏：左侧以图像为主，右侧以阅读为主。右侧可以在宽屏保持适度 sticky，但不把所有信息做成相同规格卡片。

900px 以下改为单栏，顺序固定为：18 张塔罗、本卦、动爻、变卦。塔罗仍为三列 × 六行，每组三张保持清楚的爻位分组。所有容器设置 `min-width: 0`、图片使用受限宽度，360px 下不得产生横向溢出。

## 错误处理

- 结果快照结构损坏：拒绝打开并返回 Unity 介绍页，保留明确本地化提示。
- 算法结构与知识索引不一致：展示计算错误，不猜测卦名或上下卦。
- 卦级或爻级正文缺失：保留结构信息，正文区显示“待录入”，不阻止查看其他已存在资料。
- 牌面图片加载失败：继续使用现有 `TarotCard` 文字回退。

## 测试与验收

纯函数测试至少覆盖：

1. 无动爻：知识快照 `changed` 为 `null`，原始算法变卦仍保持计算事实。
2. 单动爻：爻辞严格按本卦和 1-based 爻位读取。
3. 多动爻：所有动爻顺序递增且分别读取正确资料。
4. 六爻全动：本卦、六个动爻和变卦映射正确。
5. 64 卦结构索引完整、卦序唯一、上下卦与线型一致。
6. 本卦和变卦使用同一文王卦序索引。
7. 经典原文与现代简释字段严格分离。
8. 缺失正文返回结构化不可用状态。
9. 保存后重新打开结果不调用随机函数、不改变 18 张牌和六爻。
10. 三种现有语言新增文案完整。

页面和样式验证覆盖 360、768、1024、1440px：桌面双栏、移动端顺序、3 × 6 牌图区、浮层操作、无横向溢出及浏览器控制台无新增错误或警告。

最终运行：

```bash
npm test
npm run build
```

## 明确停止点

第三阶段完成后立即停止。不得新增六爻 × 三张塔罗融合章节，不得生成塔罗牌义、融合文案、综合建议或 AI 内容；这些属于后续阶段。
