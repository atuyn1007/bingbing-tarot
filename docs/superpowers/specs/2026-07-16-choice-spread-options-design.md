# 二选一牌阵选项绑定设计

## 目标

让用户在抽牌前用自己的语言定义选项 A 与选项 B，并让这对文本从提问、洗牌、结果、AI 解读到历史回放始终保持固定：左侧永远是 A，右侧永远是 B。用户在结果页不需要再回忆左右分别代表什么。

## 范围

- 仅影响 `choice`（二选一）牌阵。
- 不改动其他牌阵的提问、抽牌或结果流程。
- 保留既有抽牌数量、牌位、随机抽牌、路由与视觉配色。
- 在已有的阅读状态与历史快照中增加两个可选字段：`choiceA`、`choiceB`。

## 输入流程

1. 用户选择二选一牌阵后，先输入问题。
2. 同一页面显示两个必填文本输入：选项 A 与选项 B。
3. 确认抽牌仅在问题、选项 A、选项 B 都去除空白后非空时可执行。
4. 确认时保存该对文本；开始洗牌后不得根据牌序、结果或展示宽度交换 A／B。
5. 非二选一牌阵不显示这两个输入，也不需要填写它们。

## 绑定与展示

现有二选一五张牌的结构保持不变，但语义固定如下：

| 区域 | 固定归属 | 牌位 |
| --- | --- | --- |
| 左列 | `choiceA` | 未来牌、现在牌 |
| 右列 | `choiceB` | 未来牌、现在牌 |
| 中央／下方 | 我的状态 | 当事人牌 |

结果页顶部固定显示问题。每个分支的牌组上方先显示字母与完整选项文案，例如 `A｜继续主动联系`；不再只显示泛化的“选项 A／选项 B”。“我的状态”保持独立于两个选项之外。

## 数据与兼容性

- 本次阅读状态新增 `choiceA`、`choiceB`，只在 `choice` 牌阵有值。
- 阅读记录和历史快照应保存同一对字段，使历史、AI 文本和后续展示可回放真实含义。
- 旧记录没有这两个字段时必须仍可打开：使用本地化的既有默认标题作为兼容回退，不伪造用户原始选择文本。
- AI／规则阅读若使用位置名称，A、B 的位置名称应使用本次快照中的文案，而不是固定位置词。

## 移动端与可访问性

- 移动端依然按阅读顺序展示：问题 → A 文案与两张牌 → B 文案与两张牌 → 我的状态。
- 长选项文本允许自然换行、保持左对齐，并限制在卡牌区域内；不得造成横向溢出或把单字强行拆成极窄列。
- 输入应具有关联标签；空值时确认按钮保持禁用，并使用现有视觉体系呈现必填状态。

## 验收标准

1. 二选一牌阵开始前，用户无法在任一选项为空时抽牌。
2. 确认后，无论抽牌、翻牌或结果展示如何进行，左侧始终是 A，右侧始终是 B。
3. 结果页按“问题 → A 两张牌 → B 两张牌 → 我的状态”的语义顺序可读。
4. A／B 标题显示用户输入的完整文本，且移动端无横向溢出。
5. AI 阅读与历史快照可取得同一对文本；旧历史记录仍可读取。
6. 非二选一牌阵的流程和输出不变。

## 验证策略

- 为输入校验、A／B 状态绑定及旧记录回退补充或更新自动化测试。
- 运行现有测试与生产构建。
- 在桌面和窄屏宽度手动检查选择、抽牌、结果和历史回放的阅读顺序。
